# JobFinder GitHub updates · 2026-10-12

The user requests public program/source publication and one-click internet updates. A download icon appears in the top-right window caption before Minimize only when a newer stable version exists. Pressing it downloads, validates, installs and restarts the program while preserving personal data. Existing vacancy search UI and source integrations stay intact.

Use the user's authenticated GitHub account `4ek1st`, new public repository `JobFinder`, and stable GitHub Releases. No account/token is required by the installed program. Check latest stable release in the background at launch and every 15 minutes, with a manual check in About. Offline/no-release/current-version states do not show the icon or interrupt the user. Retry/cancel/progress are themed and localized in RU/DE; dialogs do not duplicate the caption icon.

The latest-release API gives immutable-per-check asset URLs for its tag. Expected assets: `JobFinder-portable-win-x64.zip`, `update-manifest.json`, `update-manifest.sig`. Verify the raw manifest bytes with pinned RSA-3072/SHA-256/PSS before trusting package version, size or hashes. The author signing key is Windows-DPAPI protected outside the project and release archives. Public code contains only its public key. Never send the GitHub CLI token to the installed program.

Schema 1 manifest fields: schemaVersion=1, version, tag=`v<version>`, packageFile=`JobFinder-portable-win-x64.zip`, packageSize, packageSha256, executableSha256, minimumUpdaterVersion=`0.4.1`. Versions are three/four numeric components, stable only, never downgraded. Bound metadata to 1 MiB, signature to 4 KiB, package to 200 MiB, expanded files to 400 MiB and 5000 entries. Require exact repository/asset paths; follow only HTTPS GitHub asset-CDN redirects. Cache/cooldown prevent overlapping/repeated checks; no check bypasses authentication or access restrictions.

Download to `%LOCALAPPDATA%/JobFinder/Updates/staging/<guid>`, with progress/cancellation and a temporary partial file. Validate size, SHA-256, zip traversal/absolute paths, symlinks, duplicate Windows filenames, allowed package roots, executable hash and PE version. Allowed installed roots are JobFinder.exe, README files, CHANGELOG.md, THIRD-PARTY-NOTICES and verification. A package must never replace data, profile, signing keys, helper plans, or arbitrary files.

Save current personal state and a one-time local draft/window resume state before restart. The helper is a copy of the running executable, launched hidden with `--apply-update <plan>` before the main app closes normally. It validates the plan/signature/package again, waits for the exact parent (30 s; no forced parent/unrelated-process termination), obtains an installation lock, backs up affected files and data outside the installation, then atomically replaces planned files. Preserve local data on successful update. On install/start failure roll back changed files; preserve failed data and restore the pre-update snapshot where necessary. Stop only a failed child launched by this transaction if required for rollback. Never kill by process name.

Restart with `--updated <transaction-guid>`. The new app acknowledges its actual version/PID/executable after its main window is shown. Helper verifies the acknowledgement within 45 seconds, records a private outcome/backup receipt, and retains backups. The app displays a brief success or recoverable failure status.
